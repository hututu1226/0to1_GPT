## 4. 每个周末的固定动作

### 周五晚（15 分钟）
- [ ] 读上周的 `NOTES/Wxx.md` 最后三行
- [ ] 把本周末的目标改成**一句话、一个交付物**
- [ ] 确认环境还能跑（`uv sync` 不报错）

### 周末开工时（10 分钟）
- [ ] `git status`，确认工作区干净
- [ ] 开一个 `NOTES/Wxx.md`，先写"本周目标"
- [ ] 从上周卡点开始，不要重头读

### 周末收尾（15 分钟）
- [ ] 提交代码：`git add -A && git commit -m "Wxx: 交付物"`
- [ ] 写三行：**跑通了什么 / 卡在哪 / 下周第一件事**
- [ ] 更新本文档第 0 节的进度表 + 勾选 `☐ → ☑`
- [ ] 记一笔本次花费

### 铁律
1. **不在周末启动跨周的长训练**。要么 2h 内跑完，要么能 checkpoint 续训。
2. **卡壳超 2 小时就换任务**，写进"卡点清单"，下周查。
3. **环境锁死**（`uv.lock` / `requirements.txt` 提交）。环境坏掉一个周末是最大浪费。
4. **前 6 个月一分钱不花**。Q3 才租卡。
5. **每个交付物都必须能跑起来**，不接受"我读懂了"。

## 5. 卡点与验收

### 三个卡点

| 卡点 | 周次 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| Q1 验收 | W13 | 见下 | 顺延 2 周，从 W10 重来 |
| Q2 验收 | W26 | 见下 | 顺延 2–4 周，**不要跳过** |
| Q3 验收 | W39 | 见下 | 前面做扎实了，验收自然过；过不了就回头补 W33–W35 |

### Q1 验收清单
- [ ] 关掉代码，说出 GPT-2 small 的层数 / 头数 / 维度
- [ ] 解释 `train.py` 里梯度累积、lr 衰减、weight decay 各自为什么在那儿
- [ ] 把 val loss 往下调过一截，并能说清靠改什么改的
- [ ] 回答"只有 8G 显存怎么训 124M"
- [ ] 手写 attention 与 PyTorch 版数值一致

### Q2 验收清单
- [ ] **断电测试**：合上资料，2–3h 从空文件写出能训练能采样的 GPT
- [ ] 能手写 BPE 训练（不查资料）
- [ ] 能给陌生 attention 变体指出"改了哪、为什么、代价是什么"
- [ ] 能解释"我的实现为什么比 `nn.MultiheadAttention` 慢"

### Q3 验收清单
- [ ] 有一个能真的聊天的模型（不是补全）
- [ ] 能说清 SFT 和 RL 各自改善了什么、大概多少
- [ ] 能复述 $48 的成本构成和瓶颈
- [ ] 改过一个环节，且预测方向正确

### 降级方案（只保核心）
如果进度落后 >3 周，按此顺序砍：
1. 砍 W07 / W09 / W19 / W21 / W32 这类"锦上添花"的实验
2. 消融实验（W22–W24）只做一处
3. **绝不砍**：W08（故障复盘）、W18（手写 BPE）、W25–W26（断电测试）、W29（真实训练）
