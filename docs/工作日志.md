## 三、三个阶段

一句话概括三段的关系：**① 让你会开，② 让你会造，③ 让你会交付。**

### 阶段 ① 跑通并读懂 nanoGPT

**在干什么**
把环境配好，然后拿 nanoGPT 这个现成项目从头到尾跑一遍，再把 `model.py` 和 `train.py` 读到能解释每一行的程度。开头那个"地基"指的就是环境 + PyTorch 手感（能自己写出一个训练循环、跑通 MNIST 这种），它不是独立一环，是这段的前置动作。

**为什么第一步是这个**
它是整条链里最小、最快、最不容易卡住的一段。你得先知道"一次训练长什么样"，后面手写和产品化才有参照物。跳过它直接手写，你会不知道自己在对齐什么。

**结束时你手上有什么**
- 一个锁死的能复现环境（`uv.lock` / `requirements.txt` 已提交）
- 一条**自己跑出来的** loss 曲线，和一个**自己的**模型 checkpoint
- 一份"每个超参为什么在那儿"的笔记
- 一次故障复盘：故意造一个 loss 尖刺，然后定位修好
- 一组调参对照表（lr / warmup / batch 各改一次，看差异）

**能力上的变化**
能独立跑一次训练；loss 不正常时，能说出大概是学习率、数据还是显存的问题，而不是只会重跑。

**怎么算完成**：M1 的三个问题答得上来。

### 阶段 ② 从零手写 GPT

**在干什么**
不看 nanoGPT，自己从空文件写出 attention、transformer block、训练循环、BPE tokenizer、KV cache，然后做消融实验。

**为什么值得花最长时间**
这是唯一一段会永久改变你读代码和读论文方式的部分。①里所有"别人写好的正确代码"，在这里变成"我知道它为什么这么写"。

**结束时你手上有什么**
- 一套 500–1500 行的自己的实现，带你自己的命名和抽象
- 一个自己训练的、能生成可读英文的小模型
- 一个自己写的 BPE tokenizer
- 一组消融结果：去掉 RoPE / 换 Pre-LN / 换 SwiGLU，各自差多少
- 通过断电测试

**能力上的变化**
给一段陌生的 transformer 代码，能指出它改了哪、为什么改、代价是什么。

**怎么算完成**：M2。

### 阶段 ③ nanochat

**在干什么**
跑通一个完整的 ChatGPT 类项目：tokenizer → 预训练 → SFT → RL → 评测 → 推理 → 服务。并花一次真钱（约 $48 / 2 小时 8×H100）。

**为什么放在最后**
它补的是前两段完全没碰的部分：后训练、评测、推理服务、成本。这些不需要你先会手写 GPT，但需要你懂模型内部，否则看不懂它为什么这么设计。

**结束时你手上有什么**
- 一个**能真的聊天**的模型 + 一个 Web UI
- 一次真实训练的账单，说得清 $48 花在哪
- 一份能复述的评测结果（CORE 分数、`val_bpb`、各任务分数）
- 推理基准表：延迟 / 吞吐 / 显存

**能力上的变化**
能说清 SFT 和 RL 各自让模型哪里变好、大概多少；能判断一个模型方案的瓶颈在哪。

**怎么算完成**：M3。
