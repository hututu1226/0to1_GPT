# B1 · 张量

> shape 从右往左读；广播也从右往左对齐，缺的维度在**左边**补 1。

## 核心概念

- **三件套**：`shape` / `dtype` / `device`。看到张量先看这三样
- **读 shape**：从右往左，最右边是最细的一层。`(8, 16, 64, 32)` = batch × head × token × 维度
- **变形**：`reshape` 最安全（会拷贝），`view` 要求内存连续；`permute` 只改读取顺序不移动数据
- **广播规则**：从右往左逐维比，**相等或其中一个为 1** 才能通过
- **`*` 是逐元素，`@` 是矩阵乘**。`nn.Linear(4, 8)` 内部就是 `x @ W.T + b`
- **标准正态 `N(0,1)`**：`f(x) = 1/√(2π) · e^(−x²/2)`，约 68% 落在 ±1，99.7% 落在 ±3

## 我踩过的坑

| 我以为 | 实际上是 |
|---|---|
| `randn(3,)` 传了个元组 | 调用里的逗号只是语法，`f(3,)` 和 `f(3)` 完全一样。真要传元组得写 `randn((3,))` |
| `(3,)` 是「3 行」 | `(3,)` 只是一维的 3 个元素，没有行列之分。要 3 行 1 列得写 `(3, 1)` |
| `(3,4) + (3,)` 应该按行加 | 报错 `size of tensor a (4) must match (3) at dim 1`。`(3,)` 对齐的是**最后一维** |
| 广播时会把我当成 `(3,)` | 广播时会**在左边补 1**，视为 `(1, 3)`。补 1 只往左，不往右 |
| `(3,) + (1,3)` 结果还是 `(3,)` | 结果形状取每维最大值，是 `(1, 3)`。原张量本身不变，只是广播时被当成 `(1,3)` |

## API 速查

```python
# 形状
x.shape, tuple(x.shape), x.dtype, x.device

# 变形
x.reshape(3, 4)          # 推荐，永远能用
x.reshape(3, -1)         # -1 = 自己算
x.permute(1, 2, 0)       # 换维度顺序，不移动数据
x.unsqueeze(0)           # 在最前面插一个长度为 1 的维度
x.squeeze()              # 去掉所有长度为 1 的维度
x.T                      # 转置（只对 2 维直观）

# 运算
a * b                    # 逐元素
a @ b                    # 矩阵乘：(m,k) @ (k,n) = (m,n)

# 广播：给每一列加同一个数
x + torch.randn(4)           # (3,4) + (4,)   ✅
# 广播：给每一行加同一个数
x + torch.randn(3, 1)        # (3,4) + (3,1)  ✅
x + torch.randn(3).unsqueeze(1)   # 同上，把 (3,) 掰成 (3,1)
```
